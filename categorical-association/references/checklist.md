# 注意事項清單：資料適不適合用這個方法

階段 3 判斷時用。對照 `check.json`（樣本數、最小組、期望次數、0 cell、各層樣本數、缺失）和 `profile.json`（變數型態、資料結構），替每個候選方法標示：

- ✅ 可以使用
- ⚠️ 可以使用，但需要提醒（說明問題與要用的方法）
- ❌ 不適合使用（說明原因，建議其他方法或轉介）

使用規則：

- 標有 **【MVP】** 的條目是第一版的核心 guardrails，會直接影響 ✅／⚠️／❌。
- 標有 **【文字提醒】** 的條目在第一版只寫進說明，不改變方法的主要標示。
- 「需要向使用者確認」的條目，資料無法證明，一定要問，不可以自己假設。
- **沒有列在這份清單上的狀況，不要自己發明標準或門檻**；看到可疑的地方就說出來並問使用者。

## A. Skill 可以自動從資料檢查

### 1. 期望次數太小（表格稀疏）【MVP】

- **狀況**：列聯表有些格子的 expected count 很小，常見原因是某類別很少人，或類別分太細。
- **為什麼要注意**：Pearson chi-square 用的是大樣本近似，expected count 小時，這個近似可能不可靠，P 值可能偏離真實值。重點在 expected count 和表格稀疏程度，不在總樣本數。
- **標示與做法**：
  - 2×2 表：只要有 expected count < 5，Chi-square 標 ⚠️。
  - 更大的表：有任何 expected count < 1，或超過 20% 的格子 < 5，Chi-square 標 ⚠️。
  - ⚠️ 時優先建議 Fisher exact test；大表的 Fisher 算不出來時，改用模擬的 P 值，並說明。
  - 第一版只呈現 Fisher exact P-value，不呈現 mid-P。
  - 這是 practical warning rule（Cochran 準則），不代表一定不能做卡方。
- **Skill 是否能自動判斷**：Yes。expected count 可以直接從資料算出。

### 2. 有 0 cell【MVP】

- **狀況**：某一格次數為 0。
- **為什麼要注意**：0 cell 可能讓 OR 或 RR 變成 0、∞、無法計算，或非常不穩定，實際影響取決於哪一格是 0；一般 Wald CI 在這種情況會失效。
- **標示與做法**：⚠️
  - 一定要呈現原始 cell counts。
  - 不使用 Wald CI，優先用 exact 或 score-based 方法。
  - 不自動加 0.5 continuity correction。
  - 整列或整欄都是 0，表示該類別實際上沒有觀察值：提醒使用者，並考慮移除這個空類別。
- **Skill 是否能自動判斷**：Yes。可以直接計數，也能判斷是哪一格為 0。

### 3. 某一組人數很少【文字提醒】

- **狀況**：例如一組 500 人、另一組 8 人。
- **為什麼要注意**：小組的比例不穩定，比例差、RR、OR 的 CI 會很寬。
- **標示與做法**：
  - 最小組 n < 10 時提醒。這只是**估計穩定性提醒**，不是「方法不能用」的硬性規則。
  - 最後要搭配 cell counts、expected counts、CI 寬度一起判斷。
- **Skill 是否能自動判斷**：Yes。是否觸發提醒可以自動判斷；穩不穩定要看 CI，也由 R 算出。

### 4. 資料是整理好的次數表【MVP】

- **狀況**：每一列是一種組合，另有一欄記錄人數。
- **為什麼要注意**：如果當成一人一列，樣本數會變成列數，所有結果都會錯。
- **標示與做法**：✅ 用次數欄加權後照常分析。「這欄是人數」**需要向使用者確認**。
- **Skill 是否能自動判斷**：Partial。能偵測像次數欄的欄位，但一定要問使用者。

### 5. 缺失值【MVP】

- **狀況**：分析用到的變數有缺失。
- **為什麼要注意**：刪掉有缺失的列會改變樣本。會不會造成偏誤取決於缺失機制（例如成績差的人比較不填），光看比例無法判斷。
- **標示與做法**：
  - 有 missing：一律報告刪除幾筆、占多少比例。
  - missing ≥ 5%：另外標 ⚠️，提醒可能影響結果。
  - missing ≥ 20%：加強提醒，結果可能高度受缺失影響。
  - 不會因為缺失比例高就直接標 ❌。
- **Skill 是否能自動判斷**：Yes。比例和門檻可以自動判斷；偏誤與否 Skill 判斷不了，只能提醒。

### 6. 分層後每層太小或有 0 cell【文字提醒】

- **狀況**：控制第三個變數後，有些 strata 只有幾個人，或有 0 cell。
- **為什麼要注意**：「CMH 的整體結果」和「每層的效果估計」是不同層次的問題。CMH 在總樣本夠大時仍可以做，但 strata 小或有 0 cell 時，stratum-specific OR 和 homogeneity test 都可能不穩定。
- **標示與做法**：可以報 CMH 的整體結果，但提醒不要過度解讀單一層的 OR，homogeneity test 也僅供參考。
- **Skill 是否能自動判斷**：Yes。每層 n、expected count、0 cell 都可以直接算。

### 7. 各層 OR 差很多（effect modification）【MVP】

- **狀況**：不同 strata 的效果大小或方向不同。
- **為什麼要注意**：common OR 是合併後的單一數字，各層差很多時，它代表不了整體；方向相反的層還會互相抵消。
- **標示與做法**：
  - 不論 homogeneity test 是否顯著，一律列出：每層 OR、每層 CI、效果方向、分層圖。
  - 不同 strata 的 OR 方向相反（一層 OR > 1、另一層 OR < 1）：自動標 ⚠️，不能只報 common OR。
  - homogeneity test 顯著：標 ⚠️。
  - homogeneity test 只作為輔助；P > 0.05 不可以自動判定 common OR 一定適合，因為小樣本時檢定力可能不足。
  - 沒有方向相反、但各層效果大小看起來差異較大：用文字提醒使用者自行檢視各層 OR 與 CI。**不設定倍率門檻，不由 Skill 自動下結論。**
- **Skill 是否能自動判斷**：Partial。方向相反、homogeneity test 顯著可以自動判斷；「差異較大」沒有明確標準，只能列出來提醒。

## B. 需要向使用者確認才能判斷

### 8. 重複觀察（repeated observations）【MVP】—— 需要向使用者確認

- **狀況**：同一個分析單位提供多筆彼此相關的 observation，例如前後測、同一個 outcome 量了多個時間點、同一受試者被重複列入資料。
- **為什麼要注意**：一般 Chi-square、Fisher、CMH 都假設 observation 彼此獨立，這時假設不成立。
- **標示與做法**：❌ 不使用本 Skill 的方法。二元配對資料轉介 McNemar；其他 repeated data 轉介相關資料模組。
- **Skill 是否能自動判斷**：Partial。能偵測可疑欄位（pre/post 欄名、重複的 ID），但一定要問使用者。

### 9. 叢集資料（clustered data）【MVP】—— 需要向使用者確認

- **狀況**：資料來自學校、家庭、醫院等群體。
- **為什麼要注意**：同一群體內的人可能彼此相關。CMH 分層**不能**自動解決真正的 within-cluster correlation。
- **標示與做法**：
  - 學校、家庭、醫院只是一般的 categorical covariate，而且控制後可以合理把個體視為獨立：可以考慮拿來分層。
  - 存在真正的 cluster correlation：❌ 轉介 clustered／correlated data 模組。
- **Skill 是否能自動判斷**：Partial。能偵測像群組編號的欄位，但有沒有群內相關要由使用者判斷。

### 10. 趨勢檢定與變數型態【MVP】—— 需要向使用者確認

- **狀況**：類別有順序（low／medium／high），或用數字代碼表示（1、2、3、4）。
- **為什麼要注意**：數字代碼不代表有順序（1 = 男、2 = 女；血型編成 1–4 都沒有順序）。趨勢檢定假設類別有自然順序，而且要給每個類別一個 score。
- **標示與做法**：
  - 第一版正式支援的趨勢相關分析只有兩種，名稱不可混用：
    - **A. Y 為 binary outcome、X 為 ordinal explanatory variable → Cochran-Armitage trend test** ✅
    - **B. X 與 Y 都經使用者確認具有自然順序 → Linear-by-linear association test** ✅
  - 兩種情況都必須先由使用者確認類別真的有自然順序，不能因為資料被編成 1、2、3、4 就當成 ordinal。
  - **X 為 binary nominal（例如性別、治療組）、Y 為 ordinal（例如滿意度低／中／高）**：不要因為 X 只有兩類或可以編成 0／1，就把它當成 ordinal，也不要自動歸到 linear-by-linear。標成「**需要確認分析目的**」，第一版不自動推薦趨勢檢定；可以先用 Chi-square 看有沒有關聯，並說明這種情況第一版沒有專門的方法。
  - score 不是自然等距時（例如每天 0、<1、1–2、3–5 小時），請使用者確認 score 怎麼設定，並提醒結論可能隨 score 改變。
  - nominal 變數做趨勢檢定：❌，改用 Chi-square。
  - 趨勢檢定主要抓線性趨勢，要和一般 Chi-square 的結果對照。
- **Skill 是否能自動判斷**：Partial。outcome 是否二元可以自動檢查；有沒有順序、score 怎麼給，一定要問。

### 11. 連續變數被切成類別【文字提醒】—— 需要向使用者確認

- **狀況**：例如年齡切成 < 40／≥ 40。
- **為什麼要注意**：會損失資訊；結論取決於 cut-off；看過資料才挑的 data-driven cut-point 會造成偏誤。
- **標示與做法**：
  - 問使用者切點的來源（事先決定或通用標準），並提醒結論取決於切點。
  - 如果使用者真正想問的是「predictor 越大，outcome 怎麼變」，建議轉介 logistic regression 等模型，不要硬切類別。
- **Skill 是否能自動判斷**：Partial。用 `recode` 切類別時可以自動觸發提醒；切點的來源要問使用者。

### 12. 研究設計與抽樣【MVP】—— 需要向使用者確認

- **狀況與做法**：
  - **case-control**：risk、RR、risk difference 一般不適合直接從樣本計算來解釋母體風險 ❌；OR 可以使用 ✅。
  - **cross-sectional**：可以比較比例或 prevalence，但不要說成「未來發生的風險」⚠️。
  - **cohort／randomized experiment**：RR 通常可以合理使用 ✅。
  - **non-probability／convenience sample**：⚠️ 即使可以計算檢定結果，也不能直接宣稱代表整個母體；要做 population inference，需要額外的抽樣假設。
- **Skill 是否能自動判斷**：No。資料本身看不出研究設計。

### 13. 要不要控制第三個變數【MVP】—— 需要向使用者確認

- **狀況**：資料裡有其他類別變數。
- **為什麼要注意**：confounder 可能製造、隱藏甚至反轉關聯；但控制 mediator 會把想看的效果拿掉。
- **標示與做法**：
  - 不要看到第三個變數就自動跑 CMH；先問使用者的研究問題，以及這個變數扮演什麼角色。
  - 可能是 confounder：可以考慮分層。
  - 可能是 mediator：不應機械式地控制。
  - **本 Skill 第一版的 CMH 模組限制在 X、Y 為二元，Z 為 categorical stratification variable。** 這是本 Skill MVP 的範圍，不是 CMH 理論上的限制。
  - Z 是 continuous，或使用者想同時控制多個 covariates：轉介 regression model 模組。
- **Skill 是否能自動判斷**：Partial。Z 的型態可以自動檢查；變數的角色一定要問。

## C. 主要屬於結果解釋提醒（階段 5 的輸出規則）

### 14. P 值解釋【MVP】

- **狀況**：把 P 值當成關聯強弱或有無。
- **為什麼要注意**：P 值受樣本數影響。大樣本時，很小的差異也會顯著；小樣本時，實質差異也可能不顯著。
- **標示與做法**：
  - p < 0.05 不能說關係很強；p > 0.05 不能說完全沒有關係。
  - 一律同時呈現 effect size 和 confidence interval。
  - 不顯著時寫「證據不足（evidence insufficient）」，不寫「沒有關係」。
- **Skill 是否能自動判斷**：Yes。是輸出規則，不需要問。

### 15. 相關不等於因果【MVP】

- **狀況**：觀察性資料發現關聯。
- **為什麼要注意**：可能有沒控制到的干擾變數。
- **標示與做法**：原則上使用 association language；不自動產生「造成、導致、使得」這類因果文字，除非研究設計真的支持因果推論（例如使用者在第 12 條確認是隨機分派的實驗）。
- **Skill 是否能自動判斷**：Yes。是輸出規則，預設使用關聯用語。

### 16. OR 不是 probability 的倍數【MVP】

- **狀況**：把「OR = 2」說成「機率是兩倍」。
- **為什麼要注意**：OR 是 odds 的倍數；只有結果少見時，OR 才接近 RR。
- **標示與做法**：OR 一律解釋成 odds 的倍數；不是 case-control，而且資料允許時，同時報 RR 幫助理解。
- **Skill 是否能自動判斷**：Yes。是輸出規則。
